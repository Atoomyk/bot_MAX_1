## 📋 Реализованные сценарии

### ✅ Вариант 1: Пациент сразу соглашается
1. МИС отправляет запрос → Бот создаёт чат
2. Бот отправляет сообщение с кнопкой "Согласен"
3. Пациент нажимает "Согласен" → Фиксируется в БД
4. Бот отправляет ответ с ссылкой в МИС
5. За 24ч: Напоминание без кнопки
6. За 15м: Напоминание со ссылкой на чат

### ✅ Вариант 2: Согласие за 24 часа
1. МИС отправляет запрос → Бот создаёт чат
2. Бот отправляет сообщение с кнопкой
3. Пациент НЕ нажимает → Бот отправляет ответ в МИС
4. За 24ч: Напоминание с кнопкой "Согласен"
5. Пациент нажимает "Согласен" → Фиксируется в БД
6. За 15м: Напоминание со ссылкой на чат

### ✅ Вариант 3: Пациент не соглашается
1. МИС отправляет запрос → Бот создаёт чат
2. Бот отправляет сообщение с кнопкой
3. Пациент НЕ нажимает
4. За 24ч: Напоминание с кнопкой
5. Пациент НЕ нажимает
6. За 15м: Напоминание БЕЗ ссылки
7. Ссылка не отправляется

### ✅ Позднее согласие
- Если пациент нажал "Согласен" после 15-минутного напоминания
- Проверяется: не началась ли консультация?
- Если нет → отправляется ссылка немедленно

### ✅ Отмена консультации
- МИС отправляет PUT запрос с `status=CANCELLED`
- Обновляется статус в БД
- Отправляется сообщение пациенту
- Напоминания проверяют статус и не отправляются

## ⚠️ Важные замечания

### Телефон пациента
- Если не передан в запросе → сессия создаётся с `user_id = NULL`
- Логируется как `patient_not_found`
- Сообщения не отправляются пациенту
- Можно добавить fallback: отправка в чат ТМК

### Формат даты
- Входной: `2026-01-25T14:00:00.000+0300`
- Используется локальная timezone (Moscow)
- Подписывается в сообщениях: "(Московское время)"

### Статус CANCELLED
- Напоминания не удаляются из очереди
- Проверяются перед отправкой
- Если статус CANCELLED → пропускаются

### Рестарт сервиса
- Очередь восстанавливается из БД (~10 сек)
- Пропущенные напоминания отправляются если актуальны
- История в БД сохраняется
