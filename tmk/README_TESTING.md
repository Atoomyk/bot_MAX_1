# Инструкция по тестированию ТМК через Bruno

## Предварительные требования

1. Установите [Bruno](https://www.usebruno.com/) - современный API-клиент
2. Убедитесь, что бот запущен и API сервер работает на порту 8085
3. Проверьте, что в `.env` указаны переменные:
   - `MIS_API_TOKEN` - токен для авторизации
   - `MIS_API_PORT=8085`
   - `SFERUM_ACCESS_TOKEN` - токен для MAX API

## Структура коллекции Bruno

Создайте новую коллекцию "TMK Integration" со следующими запросами:

## Сценарии тестирования

### Сценарий 1: Пациент сразу соглашается
1. Создайте ТМК с `scheduleDate` через 48 часов от текущего времени
2. Проверьте, что пациент получил сообщение с кнопкой "Согласен"
3. Нажмите кнопку "Согласен" в боте
4. Проверьте, что согласие зафиксировано в БД
5. Дождитесь напоминания за 24 часа (или измените время в БД для теста)
6. Дождитесь напоминания за 15 минут со ссылкой

### Сценарий 2: Пациент соглашается за 24 часа
1. Создайте ТМК
2. Не нажимайте кнопку "Согласен"
3. Дождитесь напоминания за 24 часа с кнопкой
4. Нажмите кнопку "Согласен"
5. Дождитесь напоминания за 15 минут со ссылкой

### Сценарий 3: Пациент никогда не соглашается
1. Создайте ТМК
2. Не нажимайте кнопку "Согласен"
3. Дождитесь всех напоминаний
4. Проверьте, что ссылка НЕ отправлена

### Сценарий 4: Позднее согласие
1. Создайте ТМК с `scheduleDate` через 10 минут
2. Не нажимайте кнопку сразу
3. Дождитесь напоминания за 15 минут (без ссылки)
4. Нажмите кнопку "Согласен"
5. Проверьте, что сразу пришла ссылка на чат

### Сценарий 5: Отмена консультации
1. Создайте ТМК
2. Отправьте запрос на отмену (PUT)
3. Проверьте, что пациент получил сообщение об отмене
4. Проверьте, что напоминания больше не приходят

## Проверка логов

Все события логируются в систему логирования бота. Проверяйте логи для отладки:

```bash
# Просмотр логов в реальном времени (если используется файловое логирование)
tail -f logs/bot.log
```

Основные события:
- `tmk_api.create_request_received` - получен запрос на создание
- `sferum_client.chat_created_successfully` - чат создан
- `tmk_database.session_created` - сессия сохранена в БД
- `reminder_service.reminder_added` - напоминание добавлено в очередь
- `reminder_service.reminder_sent_successfully` - напоминание отправлено
- `tmk_handlers.consent_recorded` - согласие зафиксировано

## Ошибки и решения

### 401 Unauthorized
**Причина**: Неверный токен в заголовке Authorization  
**Решение**: Проверьте, что используется правильный `MIS_API_TOKEN` из `.env`

### Пациент не найден
**Причина**: Номер телефона не совпадает с БД  
**Решение**: Убедитесь, что пациент с этим номером зарегистрирован в боте

### MAX API error
**Причина**: Проблемы с созданием чата  
**Решение**: Проверьте валидность `SFERUM_ACCESS_TOKEN`

### Напоминания не приходят
**Причина**: Сервис напоминаний не запущен или время уже прошло  
**Решение**: Проверьте логи, убедитесь что `scheduleDate` в будущем

## Быстрый тест

Для быстрой проверки всей системы:

1. Установите `scheduleDate` на **текущее время + 2 минуты**
2. Создайте ТМК через POST запрос
3. Сразу нажмите кнопку "Согласен" в боте
4. Дождитесь ~2 минуты
5. Проверьте, что пришло напоминание за 15 минут со ссылкой

**Примечание**: Напоминание за 24 часа не придёт, т.к. время уже прошло, но это нормально для быстрого теста.

## Структура Bruno коллекции

```
TMK Integration/
├── Health Check (GET)
├── Create TMK - New OMS Format (POST)
├── Create TMK - Old OMS Format (POST)
├── Cancel TMK (PUT)
└── Environments/
    ├── Local
    │   ├── base_url: http://localhost:8085
    │   └── auth_token: 543234254325432542353
    └── Production
        ├── base_url: https://your-domain.com
        └── auth_token: <your_production_token>
```

---

## Примечания

- Все даты должны быть в формате ISO 8601 с timezone: `2026-01-25T14:00:00.000+0300`
- Напоминания отправляются только если консультация не отменена (`status != 'CANCELLED'`)
- Ссылка на чат отправляется только при наличии согласия (`consent_at IS NOT NULL`)
- Для тестирования рекомендуется использовать `scheduleDate` в ближайшем будущем
