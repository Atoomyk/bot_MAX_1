# Модуль интеграции телемедицинских консультаций (ТМК)

## 📋 Описание

Модуль обеспечивает полную интеграцию между Медицинской информационной системой (МИС) и MAX-чат-ботом для управления телемедицинскими консультациями.

## 🏗️ Архитектура

### Компоненты системы

```
tmk/
├── __init__.py              # Инициализация модуля
├── models.py                # Pydantic модели для API
├── database.py              # CRUD операции с БД
├── api.py                   # FastAPI endpoints для МИС
├── sferum_client.py         # Клиент для MAX API
├── reminder_service.py      # In-memory очередь напоминаний
├── message_builder.py       # Форматирование сообщений
├── handlers.py              # Обработчики кнопок согласия
├── utils.py                 # Вспомогательные функции
└── README_TESTING.md        # Инструкция по тестированию
```

### База данных

**Таблица**: `telemed_sessions`

- Хранит все данные о консультациях
- UUID как первичный ключ
- Внешний ID из МИС (`external_id`)
- Данные пациента, врача, клиники
- Время напоминаний и отметки об отправке
- Время получения согласия пациента

### API Endpoints

#### POST `/services/telemed`
Создание новой записи на ТМК:
- Создаёт чат через MAX API
- Ищет пациента по телефону
- Сохраняет сессию в БД
- Добавляет напоминания в очередь
- Отправляет первое сообщение с кнопкой
- **Немедленно возвращает** ответ с ссылкой на чат в МИС

#### PUT `/services/telemed/{external_id}`
Отмена записи на ТМК:
- Обновляет статус на `CANCELLED`
- Отправляет сообщение пациенту об отмене
- Напоминания автоматически не отправляются

#### GET `/health`
Health check сервиса

## 🔔 Система напоминаний

### In-Memory очередь

- **Структура**: PriorityQueue, сортировка по времени отправки
- **Восстановление**: При старте загружаются все неотправленные напоминания из БД
- **Защита от дублей**: Атомарные обновления `*_sent_at` полей

### Типы напоминаний

**За 24 часа** (`reminder_24h`):
- С кнопкой "Согласен" если согласия ещё нет
- Без кнопки если согласие уже есть

**За 15 минут** (`reminder_15m`):
- Со ссылкой на чат если есть согласие
- Без ссылки если согласия нет

### Логика согласия

1. Пациент нажимает кнопку "Согласен"
2. Фиксируется `consent_at` в БД
3. Проверка: не прошла ли консультация?
4. Если 15-минутное напоминание уже ушло, но консультация ещё не началась → отправляем ссылку сразу

## 📝 Форматы данных

### Телефон
- Входной формат: `+79787199457`
- Нормализация: автоматическая (`8` → `+7`, `9XXX...` → `+7XXX...`)

### Дата/время
- Входной формат: `2026-01-25T14:00:00.000+0300`
- Хранение: PostgreSQL TIMESTAMPTZ
- Отображение: "30.12.2018", "12:00 (Московское время)"

### ОМС
- Новый формат: только `number` (16 цифр)
- Старый формат: `series` + `number`

## 🔄 Жизненный цикл консультации

```
1. МИС → POST /services/telemed
   ↓
2. Создание чата MAX (3 попытки, 1 мин между попытками)
   ↓
3. Поиск пациента по телефону
   ↓
4. Сохранение в БД + расчёт времени напоминаний
   ↓
5. Добавление в очередь напоминаний
   ↓
6. Отправка первого сообщения с кнопкой
   ↓
7. Ответ МИС со ссылкой на чат
   ↓
8. [За 24ч] Напоминание ± кнопка согласия
   ↓
9. [За 15м] Напоминание ± ссылка на чат
   ↓
10. Консультация завершена
```

### Отмена консультации

```
МИС → PUT /services/telemed/{id} (status=CANCELLED)
   ↓
Обновление статуса в БД
   ↓
Отправка сообщения пациенту
   ↓
Напоминания проверяют статус и не отправляются
```

## ⚠️ Ограничения

- Один экземпляр сервиса (нет распределённой очереди)
- Задержки ±1-2 минуты допустимы
- Повторные попытки создания чата: 3 раза с интервалом 60 сек
- После рестарта: восстановление из БД занимает ~10 сек

## 🐛 Устранение неполадок

### Напоминания не приходят
- Проверьте: `reminder_service.running == True`
- Проверьте: `schedule_date` в будущем
- Проверьте: `status != 'CANCELLED'`

### Ошибка создания чата
- Проверьте: валидность `SFERUM_ACCESS_TOKEN`
- Проверьте: доступность `https://ejd-api.sferum-dev.ru`

### Пациент не найден
- Проверьте: телефон в формате `+7XXXXXXXXXX`
- Проверьте: пациент зарегистрирован в боте

## 👨‍💻 Разработка

### Добавление нового типа напоминания

1. Добавьте поля в БД (`reminder_X_at`, `reminder_X_sent_at`)
2. Обновите `ReminderService._load_pending_reminders()`
3. Добавьте метод `_send_X_reminder()`
4. Обновите расчёт времени в `api.py`

### Добавление нового endpoint

1. Добавьте Pydantic модели в `models.py`
2. Создайте endpoint в `api.py`
3. Добавьте CRUD операции в `database.py`
4. Обновите тесты в `README_TESTING.md`
